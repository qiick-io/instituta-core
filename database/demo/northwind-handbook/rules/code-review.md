# Code review checklist

## Before approving

- The change does one thing and its title says what.
- Names are full words; no abbreviations.
- Tests cover the behaviour, including the failure path.
- No secrets, personal data or production URLs in the diff.

## Tone

Comments explain why, propose a fix, and say whether they block. See [[Brand voice]] for the tone of written feedback.
